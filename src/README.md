# Параллельное программирование (Методы Монте-Карло)

## Цель работы
Решить задачу вычисления площади круга методом Монте-Карло линейным и параллельным способом, сравнить время исполнения программ.

## Задание
Запрограммировать параллельную программу, реализующую алгоритм метода Монте-Карло для вычисления площади круга.
Каждый процессор / поток должен генерировать свое пространство случайных чисел и обрабатывать его.
В результате необходимо получить: общее количество точек \(n\), количество попавших в область точек \(m\), приближенное значение числа (pi) и погрешность вычисления.

## Теоретическая часть
Метод Монте-Карло основан на генерации случайных точек. Рассматривается единичный круг, вписанный в квадрат.

Площадь квадрата равна \(4\). Если сгенерировать \(n\) случайных точек в квадрате и посчитать \(m\) точек, попавших внутрь круга, то приближенная площадь круга вычисляется как:
$$
S \approx \frac{4m}{n}
$$

Погрешность вычисления:
$$
\varepsilon = \left| \frac{4m}{n} - \pi \right|
$$

В параллельных реализациях общее число точек \(n\) делится между вычислителями. Каждый процесс / поток генерирует свою последовательность с уникальным сидом (seed) для исключения дублирования. Затем результаты суммируются.

## Технологии распараллеливания
В работе реализованы 4 программы:
1. **Python (линейная):** `linear.py`
2. **Python (параллельная):** `parallel.py` — используется модуль `multiprocessing` (4 процесса). Это обходит ограничение GIL (Global Interpreter Lock) в Python.
3. **Java (линейная):** `Linear.java`
4. **Java (параллельная):** `Parallel.java` — используется `ExecutorService` (4 потока). Потоки в Java работают быстрее процессов, так как разделяют общую память.

## Анализ результатов и выводы

В ходе работы были сделаны следующие выводы:

**Ускорение внутри языков:**
* В Python параллельная версия (4 процесса) ускорила работу в **2.71 раза** (эффективность 67.7%). Накладные расходы на создание процессов, их запуск и межпроцессное взаимодействие (IPC) не позволили достичь идеального ускорения в 4 раза.
* В Java параллельная версия (4 потока) ускорила работу в **3.14 раза** (эффективность 78.5%). Потоки внутри JVM имеют меньшие накладные расходы на переключение контекста, поэтому масштабирование прошло лучше.

**Сравнение языков (Java vs Python):**
* Параллельная программа на Java (**0.1219 с**) оказалась быстрее линейной программы на Python (**2.1987 с**) примерно **в 18 раз**.
* Параллельная Java-программа быстрее параллельной Python-программы в **6.7 раза**.

**Почему Java быстрее Python?**
* **JIT-компиляция:** Java компилирует байт-код в машинный код прямо во время выполнения, что делает циклы генерации случайных чисел в разы быстрее, чем в интерпретируемом Python.
* **Разница потоков и процессов:** В Python для обхода GIL пришлось использовать *процессы*. Процессы изолированы друг от друга, требуют отдельной памяти и затрат на передачу данных. В Java использовались *потоки*, которые живут в одном процессе, делят общую память и создаются/переключаются намного быстрее.
* Если бы в Java использовались отдельные процессы (через `ProcessBuilder`) для данной задачи, программа работала бы медленнее из-за затрат на запуск новых JVM, но все равно, скорее всего, обогнала бы Python благодаря скорости самого языка.

**Итог:** Наибольший прирост производительности **(для данной задачи)** дает комбинация быстрого языка (Java) и правильной модели параллелизма (легковесные потоки вместо процессов).
